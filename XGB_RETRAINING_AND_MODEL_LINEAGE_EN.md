# Public project XGBoost continuation (rc6)

## R5 browser training choices

The current browser guide (`python3 start_compag.py`) distinguishes the operational command described below from a separate **Paper protocol** option. Operational performs an actual new fit but does not run a holdout or cross-validation. When a snapshot contains only one original card or bulk-accepted prior predictions, its saved model can support functional continuation but has no independent-label or paper-performance claim. The guide now displays the saved policy, row count, group information, training receipt and model hash.

Paper protocol uses `tools/train_paper_xgb_round.py` on a sealed cumulative review snapshot. It rejects every `bulk_accept` row and requires individual human review from at least six distinct original-card groups, both classes, and valid group-safe train/heldout/five-fold splits. On eligible data it applies the recovered paper settings: a grouped held-out split, five grouped search folds, 30 sampled configurations, grouped inner early stopping, train-fold Safe-SMOTE when feasible, and a fresh CUDA XGBoost fit. It saves search, split, held-out, recipe, model and checksum records. It applies a method to **new** review data and does not reconstruct the historical r92 training set or certify the paper's reported accuracy. Current browser uploads receive unique saved photo names; old snapshots that reused `original.jpg` for multiple different uploads cannot be silently regrouped. Create new sessions and reviews for those photos before requesting paper-protocol training.

`r92` remains the unchanged, separately supplied native feature-state archive. Its classifier assists the first review. A project fit is a new classifier over the user's cumulative, explicitly reviewed candidates. It is not paper r93 or a reconstruction of historical r92 fitting.

## Data boundary

`r92 select-review` writes optional `image,id` keys from a complete full-card inference. Its current policy ranks by absolute **raw XGBoost** distance to the recorded threshold. The project reviewer always supplies every valid scored candidate, with the bound shortlist as rank metadata and a filter. The latest physical `accept`, `flip`, `sus_accept`, `sus_flip`, `skip`, `delete`, or `bulk_accept` event for each candidate is effective. `delete` has no class or training weight and excludes the mask from the active pool, snapshot and export; the original scored record remains immutable. The explicit Accept remaining action records the frozen effective model prediction for every currently undecided candidate across all cards, independently of display filters, as `bulk_accept` with factor 1.0. It is user-confirmed model acceptance, not individual human inspection or independent ground truth. A batch receipt and exact pre-batch log permit Undo last batch until any later event changes the log. `r92 plan-review` reports eligible, deleted and bulk-accepted counts and included/excluded identities before finalization. Default `--scope reviewed` commits every effective labelled decision, including those outside Top-K; `--scope all` requires a terminal event for every scored candidate; `--scope locked --selection FILE` retains an intentionally restricted batch. Skip and delete are audited but excluded from training. Repeated identical candidates keep one cumulative row. A changed committed label or exclusion requires a new immutable snapshot and `--correction-revision`; changed geometry remains rejected by the bound inference checks.

The immutable snapshot records original-card grouping, source image/tile/mask hashes, full feature order, source feature-state identity, source score, effective label, review event, declared scope, optional selection and inference hashes, and cumulative parent snapshot. Human and software-test labels cannot be silently mixed. A committed review batch is **not** an exhaustive image annotation.

## Fresh fit

`r92 train-xgb --policy small-data-operational` performs a new XGBoost 2.1.1 CPU fit from scratch on all eligible cumulative rows, with a fixed parameter set. It requires both binary classes. It makes no holdout, cross-validation, group-generalization, or scientific-performance claim. This named profile permits a functional check from a small number of cards. The retained canonical standard trainer still has its separate group-safe search/validation guard; this command does not claim to execute it or to reproduce historical parameter selection.

The 93 predictors are taken only from the frozen native feature schema. Project training computes each imputer median on training rows only; an all-missing column uses its named frozen r92 fallback. Missing features are not zero filled. Frozen r92 PCA/prototype/feature state and class map are copied unchanged into the new project bundle. A deliberate feature-state change requires regeneration under a new identity and is outside this fixed-state command.

The fit records the source review multiplier (1.0 for accept/flip, 0.4 for uncertain accept/flip, 0 for skip) plus retained prior-correctness, uncertainty, border, and tiny-negative factors. These are exposed per candidate in `TRAINING_RECIPE.json`. The new `classifier.ubj`, imputer, feature schema, transform state, hashes, parameters, split roles, and actual boosting-round count are sealed in `PROJECT_MODEL_MANIFEST.json`. `verify-project-model` reopens and checks all members and the 93-feature order. `activate-model-set` checks the bundle against its exact snapshot before atomically changing `LATEST_MODEL_SET.json`. Older model-set directories remain selectable.

## Evidence levels

The rc6 software-test fixture exercises an actual 51-row snapshot, numerical fresh fit and original-coordinate COCO export, including one confident model-non-CJ candidate outside Top-50 flipped to CJ. The approved diagnostic photos are prior diagnostic examples, not independent biological validation. A human-reviewed project model requires the user's own saved decisions. No historical fit-time split or accuracy is inferred from the fixture.
