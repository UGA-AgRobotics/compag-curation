## Changes

- `r92_review.make_session` now creates `compag-r92-review-state/v2` from the entire verified scored CSV. An optional selection CSV is bound as recommendation metadata and rank. Old restricted v1 states retain their prior behavior until deliberately expanded.
- `r92_review.R92ReviewSession` adds project-only model facts, actual bound shortlist membership, independent effective human action status, and physical event-order semantics. Skip and Delete supersede an earlier class decision. Delete removes the mask from the active review pool and downstream outputs while keeping the immutable scored record. Accept remaining previews the undecided count across all cards, then requires explicit confirmation and records frozen effective model decisions as distinct `bulk_accept` actions. A hash-bound backup allows Undo last batch while the log remains unchanged. The existing Only_codes reviewer code path and default page remain unchanged.
- `r92_review_ui.py` supplies independent AND-composed filters for machine prediction, model margin, shortlist, review status, and human label. A raw-XGBoost prediction view is separate from the effective hybrid decision. Mismatch composes with other filters. Deleted masks are hidden by default; Reset clears every narrowing control and reveals them. List pagination uses stable keys and does not truncate the pool. The displayed model prediction and difficulty remain fixed after human action.
- `only_codes.review_web` selects this page only for an r92 project adapter; its AL panel receives the bound recommendation rather than a guessed sibling `al_candidates.csv`.
- `r92_project_model.review_plan` lists included and excluded identities plus deleted and bulk-accepted counts before commit. `finalize_review` defaults to `--scope reviewed` and includes every eligible effective label, including outside the shortlist. `--scope all` requires a terminal event for every scored candidate; `--scope locked --selection FILE` is the deliberate restricted batch. Skip, Delete and unreviewed candidates do not become training labels. A previously committed mask can be removed only with an explicit correction revision.
- `r92_model_set.complete_xgb_round`, the CLI, and the laptop guide no longer require a 50-row selection for the primary reviewed-decision path. `export-original-coco` works from committed snapshot rows and remains a partial annotation export. The older `r92 export` remains a strict exhaustive tiled COCO route.
- `r92_review.expand_session` copies a restricted v1 state to a new v2 directory after checking bound score, model, tile/project, selection, candidate identity, event semantics and navigation. Event CSV bytes, timestamps and row order are copied; the old directory is untouched. An expansion receipt links both states.

## User path

Start with `FIRST_RUN_COMPLETE_ROUND_EN.md`. To upgrade an existing restricted session, run `compag-curation r92 expand-review --old-state OLD_STATE --new-state NEW_STATE`, then reopen `NEW_STATE` with the same `--scored` and `--tiles`. For a new session, pass an optional `--selection` solely to display Top-K rank. During review, Delete mask excludes the selected proposal; Preview / accept remaining first reports all still undecided model predictions across the complete scored pool and asks for confirmation. Bulk accepted labels are model derived, with factor 1.0, and remain identified as such in the snapshot. Before training, run `compag-curation r92 plan-review --state STATE --scope reviewed`. Use `complete-xgb-round --scope reviewed` without `--selection` for an ordinary labelled batch; choose `all` only when every scored candidate has an explicit terminal event. Any later correction of committed labels or deletion needs a new immutable round output and `--correction-revision`.
