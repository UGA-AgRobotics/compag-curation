# COMPAG Curation 1.9.4rc9 — paper XGBoost and existing YOLO in the browser (R5)

Run `python3 start_compag.py` from this complete repository to open the local browser workflow. The four startup files remain included and byte-identical to R4. The installed `src/compag_curation` engine, application wheel, native r92 model, and ten-photo ZIP remain unchanged. R5 changes the source-level browser/launcher workflow and adds two optional helpers and one hash-pinned YOLO dependency overlay.

The Train step now offers explicit **Operational** and **Paper protocol** XGBoost choices and shows saved training evidence after a fit. Operational training really fits a new XGBoost classifier from eligible review decisions with a fixed recipe. It has no held-out evaluation or group cross-validation. A fit dominated by bulk-accepted model predictions is a functional continuation, not independent human ground truth or paper-method validation.

Paper protocol applies the documented group-aware XGBoost settings to **new** review snapshots: original-card grouping, a held-out card split, five group-safe folds, 30 sampled configurations, group-safe early stopping, and a fresh fit. It requires CUDA and individually reviewed, correctly identified data from at least six independent original cards with both classes and valid folds/splits. Bulk-accepted predictions are rejected before fitting; a one-card, all-bulk snapshot cannot use this option. It does not reproduce historical r92 training or establish the paper's reported accuracy. New browser uploads receive distinct saved photo names for grouping; old snapshots that reused `original.jpg` for different uploads need new sessions and reviews rather than a silent identity change.

After an XGBoost round, the browser can attach the **existing** one-class CJ YOLO segmentation checkpoint for the next full-card inference. The checkpoint stays in a user-selected local package outside the public repository; the package folder contains `MODEL_MANIFEST.json` and `weights/best.pt`. When needed, the browser prepares a separate Ultralytics 8.4.26 environment from a hash-pinned overlay; the science-GPU environment is not modified. The segmentation checkpoint supplies verified boxes and confidences on every prepared tile. Prompt uses its boxes with SAM2; Fusion combines its support with XGBoost decisions; Both enables both; Off uses the XGBoost/SAM2 path. Its segmentation masks are not inserted as proposals. Later XGBoost retraining carries forward the selected, verified YOLO inference setting. This R5 workflow does **not** train a new YOLO checkpoint. The optional YOLO routes are outside the paper's canonical YOLO-off result.

The browser continues to use the existing review, deletion, bulk-accept, saved-state, interruption-resume, and next-photo workflow. User photos, reviews, fitted project models, and the optional YOLO environment remain outside the source repository. These are local software checks, not biological validation. This is a local delivery candidate; no GitHub repository or Release publication is claimed.
